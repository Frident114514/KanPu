# KanPu 安卓琴谱阅读器开发文档

版本：v0.7（全屏铺满、封面、琴谱单视图与简化反色）  
编写日期：2026-11-09  
状态：应用开发中；逐项完成情况见第 11 节验收清单。  
用途：作为后续界面设计、功能实现和验收的共同依据。

## 1. 产品目标与设计原则

制作一款在安卓手机和平板上运行的琴谱阅读应用，暂用项目名 **KanPu（看谱）**。以练琴时清晰看谱、稳定翻页为核心，支持本地 PDF 导入、琴谱单分类、逐页自动翻页和难点段落的手动指法标注。

第一版优先满足个人离线使用。默认面向钢琴五线谱，阅读本身不限制乐器或谱面类型。界面使用简体中文，适配触屏；平板是重点体验设备，手机也必须完整可用。

- 阅读页面尽量留给琴谱，工具栏可以隐藏；不加入广告、信息流或复杂首页。
- 翻页使用短暂的横向滑动动画；等待渲染期间保留原页，不在谱面中央显示等待提示。
- 标注和计时自动保存，重新打开后继续使用。
- 保留源 PDF，导入、标注和删除书库条目均不修改用户的原文件。
- 每项功能区分“用户明确要求”“本文建议默认值”和“后续候选”，避免建议被误认为已确认需求。

### 2.2 已确认的补充说明

1. 用户已澄清原描述中的“敏感色”是“明暗色”，因此明暗主题属于第一版需求，翻页灵敏度调节不作为用户要求，也不加入第一版设置。
2. 指法由用户手动添加，主要用于某段较难的地方，记录自己熟悉的指法；无需自动识别、自动推荐或要求所有音符都标注。
3. 分类使用用户创建的“琴谱单”，例如“古典”“流行”“正在练习”。名称和所含琴谱由用户管理，不预置强制音乐类别。

### 2.3 建议默认方案

1. **双页默认按一组翻页。** 例如 `1｜2 → 3｜4`；自动翻页先用完第 1 页和第 2 页各自的时间，再换到下一组。
2. **支持 Android 8.0 / API 26 及以上作为建议基线。** 这是产品取舍，实施前根据实际设备确认；并非 PDF 渲染 API 的最低要求。
3. 第一版使用单机本地存储，无账号、无服务端、无同步功能。
4. 琴谱单保存对书库琴谱的引用；同一份谱可以加入多个单，共享指法、计时和阅读位置，不重复复制 PDF。

如果未进一步指定，后续开发可按上述建议默认值实施；发生需求调整时先更新本文相关规则与验收项。

### 2.4 本版不包含

自动识谱与指法推荐、听音跟谱、音频播放、节拍器、拍照转谱、MusicXML/MIDI 导入、云同步、在线曲谱商店、PDF 内容编辑，以及把指法写回可分享 PDF。扫描版 PDF 可以阅读和手动标注，但不能因此视为已识别出音符。

## 3. 页面与使用流程

### 3.1 信息架构

```text
书库
├── 全部琴谱 / 我的琴谱单（网格或列表）
├── 琴谱单：创建 / 重命名 / 添加琴谱 / 移除琴谱 / 排序
├── 导入：选择 PDF / 批量选择 PDF / 选择文件夹
├── 导入进度与结果
├── 琴谱详情：重命名 / 文件信息 / 从书库删除
├── 阅读器
│   ├── 页码跳转
│   ├── 指法标注模式
│   ├── 自动翻页与逐页时间设置
│   └── 本谱显示设置
└── 全局设置
    ├── 页面布局与配色
    ├── 翻页操作
    ├── 阅读常亮
    └── 缓存与存储说明
```

### 3.2 书库

- 顶部显示“我的琴谱”、搜索和设置入口，保留一个清晰的“导入”按钮。
- 琴谱默认列表；每项显示用户指定封面或首页缩略图、名称与页数。封面可上传图片或选用本谱任意 PDF 页。
- 支持按名称搜索，按最近阅读、导入时间、名称排序。
- 首次进入显示空状态：“导入 PDF 琴谱，开始练习”。
- 点击琴谱进入上次阅读位置；第一次打开从第 1 页开始。
- 重命名只修改书库显示名；删除前说明会删除应用内副本、指法和计时设置，源文件保留。
- 导入期间仍可阅读已完成导入的琴谱。
- 书库先显示可切换网格／列表的琴谱单卡片，再显示全部琴谱；搜索同时筛选琴谱单名称和琴谱名称。不显示“未分类”入口。

### 3.3 琴谱单分类

- 可以创建、重命名和删除琴谱单，名称首尾去空格后为 1—40 个字符；同一书库内不允许同名琴谱单，比较时忽略英文字母大小写。
- 琴谱单卡片显示名称与琴谱数量；空琴谱单允许保留，并提供“添加已有琴谱”和“导入 PDF”入口。
- 每个琴谱单可上传图片封面、恢复默认封面；网格和列表视图使用同一张封面。
- 琴谱单列表默认按创建时间倒序展示；首版不提供琴谱单之间的拖动排序。
- 在全部琴谱中选择一首或多首，使用“加入琴谱单”；也可在琴谱单详情页批量选择已有琴谱加入。
- 同一首琴谱可同时属于“古典”和“正在练习”。加入同一琴谱单两次不产生重复条目。
- 琴谱单内默认按加入顺序排列，支持长按拖动排序；排序只影响当前琴谱单。搜索限定当前单时应有明确范围提示。
- 从琴谱单内导入时，成功导入项自动加入该单；内容重复但已在书库中的项也可直接加入该单，无需再次复制文件。
- 导入过程中的目标琴谱单如被删除，成功项仍保留在全部琴谱中，结果页提示“目标琴谱单已删除”；不能因此丢失导入文件。
- **从琴谱单移除**只删除分类关系，琴谱、副本、指法、计时和其他琴谱单成员关系均保留；琴谱仍可在“全部琴谱”找到。
- **删除琴谱单**需要明确提示“只删除琴谱单，琴谱仍保留在书库”；批量移除支持短暂撤销。
- **从全部琴谱永久删除**需要确认，随后移除所有琴谱单内的引用及关联数据；不影响用户原 PDF。
- 全部琴谱是内置视图，不可重命名或删除。首版不支持嵌套琴谱单、自动分类或按原文件夹结构自动建单。
- 琴谱单内打开某首谱时，仍使用该谱共享的阅读位置、指法与计时；第一版读到末页只结束当前谱，不自动打开单中的下一首。

### 3.4 阅读器

- 顶栏：返回、琴谱名、更多设置；底栏：上一页、页码、下一页、指法、自动翻页。
- 顶栏眼睛图标只控制指法标记显示或隐藏，不删除标记。
- 打开后默认显示工具栏，普通阅读时约 3 秒无操作后隐藏；点中间区域可切换显示。指法编辑与无障碍服务启用时不强制自动隐藏。
- 阅读器隐藏系统状态栏和导航栏，系统边缘滑动可暂时唤出；退出阅读器恢复系统栏。
- 谱页占满阅读画布，上下不留灰色带；工具栏浮在谱页上方，不挤压谱页。
- 页码在单页显示 `3 / 12`，双页显示 `3–4 / 12`；点击页码输入目标页。
- 允许双指缩放，工具栏提供“适合整页”恢复操作。初始缩放范围建议为整页比例的 1—4 倍。
- 阅读常亮默认开启，仅在阅读页面处于前台时生效，离开阅读页面后恢复系统行为。
- 计时运行时保留一个小型状态条，显示当前计时页、剩余时间和暂停按钮，不覆盖谱面主要内容。
- 所有图标均有可访问名称，主要点击目标至少 48dp；错误与计时状态不能只靠颜色表达。

### 3.5 视觉方向

采用低饱和度界面、清晰字体和适度留白。默认白纸黑谱，应用背景浅灰；指法使用与黑色音符可区分的深蓝色。工具栏与弹层使用一致的组件风格。深色界面和琴谱反色分开设置，不能因为切换系统深色模式就改变谱面的颜色。

应用图标采用深蓝底、青绿光晕与带音符的浅色谱页；保持小尺寸可辨识，并提供适配 Android 主题图标的单色层。[图标预览](应用图标预览.png)。

## 4. 琴谱显示与翻页规则

### 4.1 单页、双页与阅读位置

- 布局选项为“自动”“单页”“双页”。自动模式下，可用阅读区域高大于等于宽时显示一页，宽大于高时显示两页。
- 按应用窗口实际大小判断布局，包括分屏、折叠屏窗口变化；不能只看物理设备的旋转方向。
- 默认完整显示 PDF 页面并铺满画布，横纵方向可能分别缩放，以避免裁掉左右两侧的音符；双页各占半屏，中间保留细间距。需在设备上确认拉伸后的谱面可读性。
- 双页固定配对为 `1｜2、3｜4、5｜6……`；首版不加入封面独占一页或右起阅读规则。
- 奇数末页单独放在左侧，右侧为空，不复制最后一页，不生成可翻到的空页。
- 内部保存一个“当前阅读页”（逻辑页）。单页就是当前页；双页首次进入一组时默认左页，跳转指定页或计时进入右页时可为右页。
- 从单页第 4 页切换到双页，显示 `3｜4`，当前阅读页仍为 4；切回单页仍显示第 4 页。
- 手动翻到另一组时，当前阅读页设为新一组的左页。双页页码跳转到第 4 页时，显示 `3｜4` 并将当前阅读页设为 4。
- 翻页或跳页后新页面恢复整页适配；缩放倍率和拖动偏移不带入另一页。
- 全局布局可被单首琴谱设置覆盖；琴谱可以恢复“跟随全局”。

### 4.2 翻页手势

以下是第一版建议默认值，实际阈值在触屏设备上验证后调整。

| 操作 | 阅读模式结果 |
| --- | --- |
| 点击阅读区域左侧 30% | 上一页或上一组 |
| 点击阅读区域右侧 30% | 下一页或下一组 |
| 点击中间 40% | 显示或隐藏工具栏 |
| 从右向左滑动 | 下一页或下一组 |
| 从左向右滑动 | 上一页或上一组 |
| 双指缩放 | 缩放琴谱，不翻页 |
| 放大后单指拖动 | 平移琴谱，不触发滑动翻页 |

点击区域以整个阅读画布计算，不按双页中每张纸分别划分。工具栏、弹层和系统手势保留区域不参与画布翻页命中。

- 单页步长为 1，双页步长为一组。首页向前、末页向后均保持原位，不弹出提示，也不循环。
- 有效翻页采用约 220 毫秒的横向滑动动画，整页及指法标注同步移动；初次打开、旋转重排和同组页码变化不播放翻页动画。
- 点击在抬手且确认为轻触后处理；一旦判定为拖动或滑动，取消同一手势的点击，保证一次操作最多翻一次。
- 建议滑动识别：水平位移达到 48dp，且水平位移至少为垂直位移的 1.5 倍；实际值由真机验证后固定为首版默认参数。
- 用户可单独关闭点击翻页或滑动翻页。首版左右点击区域固定各 30%，中间区域 40%。
- 放大状态下保留侧边轻触翻页与工具栏翻页；滑动仅用于平移。首次放大时提示这一规则。
- 首版不绑定双击缩放，避免等待双击判断拖慢单击翻页。
- 指法模式禁用画布点击和滑动翻页，使用明确的上一页／下一页按钮；详见第 6 节。
- 指法模式未选数字时，点击画布中间仅切换工具栏显示，不会误添指法。
- 翻页请求串行处理，页面切换期间合并或丢弃重复请求，不排队连续跳过多个页面。一次翻页完成前不能执行下一次自动翻页。

## 5. 自动翻页

### 5.1 时间设置

每首琴谱独立保存计时方案，计时对象是 **PDF 原始页码**，不依赖单页或双页布局。

- 设置页按 PDF 页码从上到下列出时长输入框，一页一项；六页琴谱恰好显示第 1 页至第 6 页六项。页数多时列表滚动。
- 每页初始为 30 秒，旧版已自定义的页沿用其保存时长；可为每页分别输入 1—3600 秒的整数。
- 点击“保存”时一次校验全部页；任一项为空、为 0、负数或超出范围时定位并提示该页，不写入部分结果。全部有效时以事务保存每一页。
- 双页显示仍按原始页码依次消耗各页时长。开始自动翻页时立即计当前页，不设置准备倒计时。

### 5.2 单页与双页的计时语义

假设第 1 页 20 秒，第 2 页 35 秒，第 3 页 25 秒：

| 场景 | 预期行为 |
| --- | --- |
| 单页，从第 1 页启动 | 20 秒后显示第 2 页，再过 35 秒显示第 3 页 |
| 双页，从第 1 页启动 | 显示 `1｜2`，20 秒后计时页切到第 2 页，画面不变；再过 35 秒显示 `3｜4` |
| 双页，跳转到第 2 页后启动 | 显示 `1｜2`，只计算第 2 页的 35 秒，然后显示 `3｜4` |
| 双页，只有最后一页 | 只计算实际存在的那一页，不计算右侧空白 |
| 到达最后一页 | 继续完成最后一页的计时，然后停止并显示“本次演奏结束” |

状态条例如：`第 2 页 · 剩余 18 秒`。从左页进入右页计时不滚动、不换页，避免干扰视线。

### 5.3 状态与中断

使用统一状态机：`停止 → 运行中 → 暂停 → 运行中 → 完成`，其中加载页面为独立的等待状态。

暂停保存当前页剩余时间。自动暂停规则只作用于运行中或等待加载的活动会话；原本停止或完成的会话保持原状态，不能因为旋转或打开设置就出现“继续”。

| 事件 | 状态与计时规则 |
| --- | --- |
| 点击开始 | 从当前阅读页立即按该页完整时长计时；默认不回到首页 |
| 点击暂停 | 冻结当前页剩余时间；等待加载时也撤销自动提交意图 |
| 点击继续 | 从暂停时的剩余时间继续；若暂停于等待加载阶段，则重新请求目标页 |
| 点击停止 | 取消计时，保留阅读位置；再次开始按该页完整时长计算 |
| 运行时手动翻页或跳页 | 取消旧计时，目标页显示后按目标页完整时长继续运行 |
| 暂停时手动翻页或跳页 | 保持暂停，切换为页面计时阶段，目标页剩余时间重设为完整时长 |
| 首页／末页的无效翻页 | 不改变计时页，不重置剩余时间 |
| 进入指法、时间设置或本谱设置 | 自动暂停；离开后等待用户主动继续 |
| 缩放或拖动查看细节 | 自动暂停；恢复整页后也需主动继续 |
| 应用失去交互前台、锁屏、切到其他应用 | 自动暂停；返回时不补翻页面，不自动恢复 |
| 旋转、分屏尺寸或单／双页布局改变 | 暂停并保存当前计时页和剩余时间，重排完成后等待用户继续 |
| 退出琴谱／进程被系统回收 | 保存阅读位置和配置；重新打开时为停止状态，不复活后台计时 |
| 保存逐页时长 | 若当前页时长改变，保持暂停并重设为新时长；仅修改其他页时不改变当前页剩余时间 |

倒计时以单调时钟的截止时刻计算，界面刷新只负责显示剩余时间，不能靠“每秒减一”累计。系统时间手动修改不能影响翻页。生命周期重复订阅、界面重建和连续点击开始不能产生多个计时器。

首版优先保证每一页都有设定的完整阅读时间：实际换页后，以新画面可见时刻建立下一页计时起点。双页内从左页计时切到右页无需换画面，沿用连续时间轴。计时不会累积逐秒刷新误差，但真实换页或加载耗时可能延长整首演奏总时长，不承诺总耗时严格等于逐页设置之和。

### 5.4 加载与翻页竞态

- 上一页和下一页（或相邻双页组）都应预加载。当前页时间到达后，目标组内所有实际存在的页面均达到可读清晰度才提交页面切换；双页不能只等左页就绪便开始运行。
- 如果目标页尚未就绪，保留原画面，不显示居中的“正在等待下一页”提示，冻结后续计时；不能显示白屏或计时到下一页后继续跳过。
- 加载成功且会话仍有继续运行意图时，完成翻页动画后以目标页完整时长计时。超过建议 5 秒或任一页渲染失败，转为暂停并提供重试；重试成功后也需主动继续。
- 等待加载期间若用户暂停、停止、退出或应用触发自动暂停，立即撤销自动提交与续计时意图。迟到的渲染结果只能进入缓存，不得自行翻页或启动计时；用户继续时再校验目标并完成至多一次翻页。独立的手动跳页请求可以完成显示，但同样不能恢复已暂停的计时。
- 手动操作与自动截止同时到达时，以主线程事件队列串行裁决，用户已开始的手势优先；同一代页面状态最多提交一次翻页。
- 给每次计时和页面请求分配递增版本号，忽略过期回调；页面标识、当前计时页、剩余时间必须作为一次状态更新提交。

## 6. 指法标注

### 6.1 用户操作

1. 在阅读器点击“指法”，自动暂停翻页，进入明显标识的编辑模式；默认不选择数字，也不落笔。
2. 在底部主动选择数字 `1、2、3、4、5` 后，才能点击目标音符附近添加标记；再次点击同一个数字可取消选择。可附加“左手／右手／不区分”；手别默认不区分。
3. 未选择数字时点击谱面中间，只切换工具栏显示，不创建标记；收起工具栏后保留完整谱面供阅读。选择数字后可在整张谱面添加指法。
4. 点击已有标记可选中、改数字、改手别、改颜色、改字号或删除；拖动选中标记可微调位置。
5. 支持撤销／重做最近操作，建议当前编辑会话至少保留 50 步。关闭琴谱后无需保留撤销栈，但标注结果必须保留。
6. 点击“完成”回到阅读模式；已有指法继续显示，画布恢复翻页手势。

### 6.2 显示与保存规则

- 同一页可放置多个独立指法标记，只标用户需要记录的难点；未标注的页面和音符保持原样。支持和弦中的不同音符，不设置“全谱标注完成率”或必填要求。
- 指法标记默认显示在点击位置，可拖动，不能假设系统知道音符的真实位置。
- 谱面数字使用常规字重的衬线字形。中字号数字宽度以常见音符头宽度为目标，小字号更小，大字号略大；三个预设分别占页面显示高度约 1.0%、1.3%、1.7%，最终按真实 PDF 的视觉比例验收。
- 可选手别以更小的“左／右”字叠放在数字上方，避免横向撑大标记；颜色作为辅助，手别即使颜色相同仍可分辨。
- 选择标记的触摸范围可大于字形；选中态用数字下方细线表示，不使用大圆形底色遮挡琴谱。密集区域先放大再操作。重叠标记依次选择或通过小列表选择。
- 选中已有标记时清除新建标记的数字选择，避免修改已有标记后误触创建新的指法。
- 旧版已保存的 2.6%、3.5%、4.8% 字号在显示时映射到新预设，原有标注位置和数据库记录保持不变。
- 两指缩放始终优先于落笔或拖动标记。编辑模式下，未选中标记时单指拖动画布用于平移；拖动已选标记才改变其位置。
- 标记位置、字号、手别、颜色与所属 PDF 页保存到数据库；抬手完成拖动时保存位置，不逐帧写库。
- 写入失败时保持待保存状态并提示重试；不得在未落盘时展示“已保存”。
- 可一键隐藏全部指法，但不删除数据；清空本页标注需要明确确认。
- 删除一个指法可撤销；按“完成”退出时必须等待当前保存操作成功或明确展示失败。

### 6.3 坐标设计

标注绑定 `琴谱 ID + 原始 PDF 页索引 + 页面归一化坐标`。以阅读器渲染的该页完整可见边界为基准，左上角为 `(0,0)`，右下角为 `(1,1)`；该边界已包含 PDF 内置旋转与可见框的处理。

```text
页面坐标 = inverse(页面到屏幕的变换矩阵) × 触摸点
u = 页面 x / 基准页面宽
v = 页面 y / 基准页面高
字号比例 = 页面内字号 / 基准页面高
```

PDF 图像和标注必须共享同一个变换矩阵，包含单／双页偏移、整页缩放、手势缩放和平移。点击页间空隙或纸张之外不创建标注。不能保存手机屏幕像素坐标，否则旋转和换设备尺寸后会错位。

首版不做用户裁边和页面重排；后续增加时需要额外保存裁剪变换，并保持原始页面坐标稳定。标注是独立覆盖层，不写回源 PDF，也不随渲染缓存清理而丢失。

## 7. PDF 导入与书库管理

### 7.1 三种导入入口

| 入口 | 行为 |
| --- | --- |
| 导入 PDF | 系统文件选择器选择一个 PDF |
| 批量导入 | 系统文件选择器允许多选，建立同一导入批次 |
| 导入文件夹 | 选择一个目录，递归扫描该目录及全部可访问子目录中的 PDF |

使用 Android Storage Access Framework（SAF）获取用户选择的文件或目录，不要求“管理所有文件”权限。目录授权只覆盖选中的目录树；Android 11 及以上对内部存储根目录、部分 SD 卡根目录、Download 根目录、Android/data 和 Android/obb 等位置存在选择限制。界面解释系统限制，允许改选可授权子目录或通过文件多选导入。[官方文件访问说明](https://developer.android.com/training/data-storage/shared/documents-files)

### 7.2 处理流程

```text
选择文件/目录 → 建立导入任务 → 扫描候选文件
→ 流式复制到临时文件，同时计算 SHA-256
→ 内容校验、读取页数并尝试渲染首页
→ 按哈希去重 → 原子移动到正式目录
→ 数据库提交书库条目 → 异步生成缩略图 → 汇总结果
```

- 默认导入为应用私有目录的完整副本，阅读不继续依赖源 URI。原文件重命名、移动或删除不影响已导入琴谱。
- 使用 MIME 类型与忽略大小写的 `.pdf` 扩展名筛选候选，再由解析器验证内容；不能只信任文件后缀。
- 遍历使用队列和已访问文档 ID 集合，防止异常目录提供方导致重复访问或循环；不可访问子目录单独报告并继续其他目录。
- 页面内展示“扫描中：已发现 X 个 PDF”，扫描结束后展示确定的处理进度；不能在总量未知时展示虚假的完成百分比。
- 大批次按低并发流式处理，不把整个文件读入内存，不一次性为所有页生成图片。
- 同一内容哈希只保留一份，重复导入跳过文件复制后的入库步骤，并保留已有标注、时间设置和阅读位置；如果指定了目标琴谱单，仍建立缺失的成员关系。
- 同名不同内容作为不同琴谱导入，显示名可增加序号；不能按文件名直接覆盖。
- 保留来源显示名和可取得的相对目录路径，用于失败报告；分类由用户创建的琴谱单负责，递归导入不自动把原目录转成琴谱单。
- 单个文件成功后即可使用；其他文件失败不回滚已成功条目。
- 取消任务时停止继续扫描和新文件处理，清理未完成临时文件，保留已提交文件。任务取消后可重新导入，哈希去重避免重复。
- 扫描与处理进度要持久化；切后台时暂停派发新工作，正在流式复制的文件可取消并在恢复时重试。首版不承诺锁屏后持续大批量导入。
- 对支持持久授权的选择结果保存只读 URI 授权，以供中断恢复；未完成任务仍需要该授权。提供方不支持持久授权或授权失效时要求重新选择，不能假设保存一个 URI 字符串就能永久访问。全部副本成功入库后不再依赖源授权。
- 进程被回收后保留已完成结果，未完成任务标为“已中断，可继续”；继续时重新扫描授权范围并去重。权限失效则重新选择目录。

### 7.3 错误与存储规则

| 情况 | 处理 |
| --- | --- |
| 文件损坏、空文件、非 PDF | 标记失败，给出文件名与原因，继续其他文件 |
| 需要打开密码或安全方案不受支持 | 首版不提供密码解锁；提示暂不支持，不绕过保护 |
| 首页成功、后续某页损坏 | 可保留导入；阅读该页显示错误并暂停自动翻页，允许手动跳过 |
| 无权限、URI 已失效或文件被移除 | 提示重新选择，只重试受影响项 |
| 存储不足 | 停止新文件处理，清理未完成副本，保留已导入内容 |
| 没有找到 PDF | 显示扫描范围和空结果，不视为程序错误 |
| 同名或同内容 | 同名不同内容保留；同内容跳过并计入“重复” |
| 用户取消选择器 | 正常回到书库，不显示失败告警 |

结果页区分“成功、重复、失败、未处理”，列出失败原因并允许重试。汇总数量应与候选文件数一致；目录访问错误另行列示。若选择目标琴谱单，另外显示“已加入该单 X 首”，其中可以包含重复文件对应的既有琴谱，不与文件导入结果混算。

应用内删除仅移除自有副本和关联数据，不删除源文件。数据库和文件系统不能作为一个事务提交，应使用临时文件、导入状态和启动恢复检查处理崩溃：清理无记录的临时文件，核对已移动到正式目录但尚未入库的孤儿副本，恢复可确认的提交或清理对应副本；修复或移除不完整条目。每次正式导入使用独立 ID 路径，删除任务执行前核对数据库引用，避免误删重新导入的同内容琴谱。仍有有效书库引用的正式内容不能以“缓存”名义清理。

## 8. 设置设计

| 设置项 | 建议默认值 | 范围与说明 |
| --- | --- | --- |
| 页面布局 | 自动 | 自动／单页／双页，允许本谱覆盖 |
| 琴谱色彩 | 正常 | 正常／反色；可设置全局默认值和单谱覆盖 |
| 应用主题 | 跟随系统 | 浅色／深色／跟随系统，与琴谱颜色独立 |
| 指法颜色与字号 | 深蓝、中号 | 影响新建标记，已有标记保留自身样式；另提供明确的批量修改操作 |
| 点击翻页 | 开启 | 可以关闭，工具栏按钮始终可用 |
| 滑动翻页 | 开启 | 可以关闭 |
| 阅读时屏幕常亮 | 开启 | 仅阅读前台生效 |
| 清理渲染缓存 | 手动操作 | 删除缩略图和页面图片缓存，不删 PDF、标注和计时 |

反色必须改变 PDF 页面本身的显示，而非只改页面外的背景。正常模式保留原 PDF 色彩；反色只作为显示滤镜，指法图层单独处理以保持可读。配色不改变存储文件，白纸和扫描底纹都需实测。

设置优先级：本谱显式覆盖 > 全局设置 > 应用默认。计时设置按页码独立保存，首次打开时以每页 30 秒填充；翻页方向首版固定为左侧返回、右侧前进，不添加反向阅读选项。

## 9. 技术方案

### 9.1 推荐技术栈

| 部分 | 建议选择 | 作用 |
| --- | --- | --- |
| 语言 | Kotlin | 安卓原生开发 |
| 界面 | Jetpack Compose + Material 3 | 书库、工具栏、设置与适配布局 |
| 状态管理 | ViewModel + StateFlow + 单向数据流 | 集中管理阅读、标注与计时状态 |
| 异步任务 | Kotlin Coroutines | 文件读取、渲染调度、前台计时 |
| PDF | 系统 PdfRenderer + 自有阅读画布 | 精确控制分页、双页、手势与指法覆盖层 |
| 结构化数据 | Room | 琴谱、标注、逐页时间、阅读位置和导入任务 |
| 简单偏好 | DataStore | 全局显示、操作和阅读设置 |
| 文件访问 | SAF + ContentResolver / DocumentsContract | 文件多选与授权目录遍历 |
| 测试 | JVM 单元测试 + Compose/设备测试 | 计时状态、翻页规则、坐标与真实 PDF 兼容性 |

分层与单向数据流参考 Android 官方架构建议；项目规模较小时先采用清晰的包边界，避免为简单功能拆分大量 Gradle 模块。[官方架构建议](https://developer.android.com/topic/architecture/recommendations)

`PdfRenderer` 基础渲染自 API 21 可用，需要可随机读取的文件描述符；导入副本有助于统一输入。创建渲染器、打开与渲染页面放在工作线程，页面与描述符及时关闭；新系统才提供的 PDF 编辑、搜索等接口不能作为 API 26 的默认能力。[PdfRenderer 文档](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)

截至本次核查，AndroidX PDF 发布页列出 `1.0.0-beta01`。考虑本应用需要自定义双页、翻页手势和覆盖层，首选基础渲染接口；后续只有验证其系统覆盖和交互能力符合要求后才替换，不能把普通 PDF 查看器直接当作已完成的琴谱阅读器。[AndroidX PDF 发布说明](https://developer.android.com/jetpack/androidx/releases/pdf)

`compileSdk`、`targetSdk` 与依赖版本在建项时重新核对并固定到版本目录中，不采用动态 `+` 版本。本项目必须适应窗口变化：新 Android 大屏环境会改变或忽略方向锁定限制，因此“固定单页”指阅读布局固定，而非承诺物理屏幕永不旋转。[Android 自适应布局规则](https://developer.android.com/develop/adaptive-apps/guides/app-orientation-aspect-ratio-resizability)

### 9.2 逻辑分层与建议目录

```text
app/
  ui/library/           书库与导入进度
  ui/collections/       琴谱单管理、成员编辑与排序
  ui/reader/            阅读画布、工具栏、标注与时间编辑
  ui/settings/          全局设置
  domain/reader/        单双页映射、手势结果与阅读状态
  domain/autoturn/      可测试的计时状态机
  domain/importing/     导入、去重与恢复规则
  data/database/       Room 实体、DAO 与迁移
  data/repository/     数据访问边界
  data/preferences/    DataStore
  pdf/                 渲染接口、页面缓存、坐标变换
```

主要边界：`ScoreRepository` 管理琴谱和配置；`ScoreListRepository` 管理琴谱单与成员关系；`ImportCoordinator` 管理导入；`PdfRenderEngine` 提供页数、页面几何与渲染；`PageLayoutResolver` 处理逻辑页和双页映射；`AutoTurnController` 只依赖时钟、页面状态和用户事件，不依赖具体 Compose 界面。

前台秒级翻页使用可取消协程与单调时钟。WorkManager 适合可延后、需要持久化的任务，其执行时刻受系统调度影响，不用于本功能的精准页面计时；首版也不需要精确闹钟权限。[WorkManager 调度说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

### 9.3 PDF 渲染与资源管理

- 阅读器只保留当前可见页及相邻组缓存，不将整本 PDF 转成常驻内存图片。
- 对每个文档使用受控串行渲染队列；当前页优先，其次下一页／组，再次上一页／组，缩略图任务优先级最低。
- 快速翻页时取消不再需要的渲染，回调携带文档与页面请求版本；旧图片不能覆盖新页。
- 页面先提供适配屏幕的可读图像，放大后再请求更高分辨率。限制单张位图尺寸与总缓存字节；超过预算时降低分辨率或分块渲染。
- 当前位图缓存按应用堆上限约 1/3 调整，限制在 48—96 MiB；低内存设备将单页最大渲染宽度从 1800 降至 1600 像素，以尽量容纳当前页及前后相邻页。需要在目标设备实测清晰度与内存峰值，同时计入正在渲染中的位图。
- 原始 PDF 渲染图可复用，配色与指法覆盖独立绘制，切换颜色不需要重新解析整个 PDF。
- 局部页面失败不导致应用崩溃，释放失败任务资源并显示可恢复状态。
- 对来源不明 PDF 的解析与渲染建议通过隔离进程封装，主进程只传入只读文件描述符并接收受限尺寸的渲染结果；若进程退出，阅读页能重连或报告失败。这一实现需在第一阶段验证性能和内存成本。[官方渲染隔离建议](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)

### 9.4 数据模型

内部页索引统一从 0 开始，所有 UI 页码从 1 开始；转换集中处理。时间统一存毫秒，创建与修改时间用时间戳，计时运行使用单调时钟。

| 实体 | 核心字段 | 约束 |
| --- | --- | --- |
| Score | id、title、originalName、privatePath、sha256、byteSize、pageCount、sourceRelativePath、createdAt、lastOpenedAt | sha256 唯一；正式条目必须有可读副本且页数 > 0 |
| ScoreList | id、name、normalizedName、createdAt、updatedAt | normalizedName 唯一；不存复制的琴谱内容 |
| ScoreListEntry | listId、scoreId、sortOrder、addedAt | listId + scoreId 联合唯一；按单保存顺序 |
| PageGeometry | scoreId、pageIndex、width、height、geometryVersion | 记录统一坐标基准，按需读取并缓存 |
| FingeringAnnotation | id、scoreId、pageIndex、u、v、finger、hand、color、fontSizeRatio、createdAt、updatedAt | finger 为 1—5；坐标 0—1；页索引合法 |
| TimingProfile | Score.defaultDurationSec、旧版 preRollSec | 新琴谱未设置的页初始为 30 秒；旧版准备字段仅为兼容保留，运行时忽略 |
| PageTiming | scoreId、pageIndex、durationSec | 联合唯一；用户保存时每个 PDF 页码对应一条 |
| ReadingProgress | scoreId、logicalPageIndex、updatedAt | 每谱一条；不持久化“正在运行”的自动翻页状态 |
| ScoreDisplayOverride | scoreId、layoutMode、colorMode、paperColor、inkColor | 空值表示跟随全局；允许清除覆盖 |
| ImportJob | id、kind、sourceUrisOrTreeUri、targetListId、status、discoveredCount、completedCount、createdAt | targetListId 可空；保存批次状态；URI 不写入外部日志 |
| ImportItem | id、jobId、sourceUri、sourceName、relativePath、status、errorCode、scoreId | 支持逐项结果与恢复去重 |

数据库开启外键约束；删除琴谱级联删除其标注、计时、阅读位置与全部琴谱单成员关系，再由文件清理任务处理私有副本。删除琴谱单只级联删除成员关系，不能级联删除 Score。琴谱单数量由关系表查询，避免手工计数失真；批量添加与排序使用数据库事务。文件清理失败可重试，不能误删其他琴谱。正式发布后数据库变更必须提供迁移，不能用清库方式升级。

### 9.5 本地数据边界

第一版不申请联网、录音、位置或蓝牙权限；系统文件选择通过 URI 授权完成。日志不包含 PDF 内容、完整源 URI 和标注正文。

应用私有副本与标注在卸载后通常会被删除。首版不提供自建云备份，需显式配置 Android 系统备份与设备迁移规则，避免只恢复数据库却没有对应 PDF；默认不将琴谱和数据库纳入自动备份，设置页清楚说明。便携备份与恢复列入下一版高优先级候选，不能向用户承诺首版数据已跨设备保存。

## 10. 性能目标与测试条件

以下是开发目标，尚未实测，不作为已达到的性能声明。第一阶段记录一台实际手机和一台平板的型号、系统、内存及测试文件，形成固定基线。

| 项目 | 建议目标与测量条件 |
| --- | --- |
| 普通谱首次打开 | 本地副本、约 20 页且 ≤20MB 的测试集，首屏可读 P95 ≤2 秒 |
| 已缓存翻页 | 输入完成至动画开始 P95 ≤150ms；动画约 220ms，无白屏闪烁 |
| 自动翻页偏差 | 前台、目标页已预载、无故意暂停，单次可见翻页偏差 P95 ≤200ms；30 分钟测试中计时计算不累积逐秒刷新误差，页间呈现耗时另行统计 |
| 指法定位 | 横竖屏、单双页和 1—4 倍缩放转换后，重投影位置误差 ≤2 个显示像素 |
| 连续使用 | 约 100 页测试谱连续翻页 30 分钟，无崩溃、ANR 或持续内存增长 |
| 大批次导入 | 200 个 PDF、至少 5 层子目录，结果数量准确，书库与取消按钮仍可响应 |

低端设备、复杂扫描页和超大 PDF 单独记录降级表现，不把全部文档承诺为固定耗时。支持打开的文件不设置随意的页数硬上限，但必须受存储、渲染尺寸、单任务内存和取消机制约束。

测试素材至少包含：矢量乐谱、扫描乐谱、彩色谱、单页 PDF、奇数页 PDF、混合页面尺寸、内置旋转页、不同可见框页面、损坏页、密码文件、伪装扩展名、同名异内容和同内容异名文件。

按风险和核心体验排序，不在信息不足时承诺固定工期。每阶段都有可运行结果，阶段完成后再增加下一组能力。

## 13. 可考虑的后续点子

以下仅为建议，不自动加入第一版工作量。

| 建议 | 对练琴的价值 | 建议顺序 |
| --- | --- | --- |
| 备份与恢复 | 一次导出琴谱、指法、逐页时间，换机或重装后恢复 | 第一版后优先，避免长期积累的标注丢失 |
| 蓝牙翻页踏板／键盘按键 | 双手弹琴时用脚翻页；优先兼容发送方向键或 PageUp/PageDown 的设备 | 高 |
| 练习时录制翻页节奏 | 用户手动翻一次，记录每页停留时间，确认后生成计时方案 | 高 |
| 书签与琴谱单连续演奏 | 书签快速回到难点，在已有琴谱单基础上支持演奏结束自动打开下一首 | 中 |
| 重复段与跳转路线 | 为反复记号、D.C.、D.S. 等设置实际演奏顺序与不同轮次时长 | 中 |
| 手动裁白边 | 在小屏幕上把有限空间留给谱面，保留标注坐标兼容 | 中 |
| 导出带指法的 PDF | 便于打印和分享，需决定标记是否可编辑或扁平化 | 中 |
| 手写笔批注与练习笔记 | 补充圈画、力度和提示文字 | 后续 |
| 自动识谱与指法推荐 | 减少标注工作，但需识别音符、声部、手别并处理识别纠错 | 独立研究阶段 |

当前最值得优先讨论的是“踏板翻页”和“录制翻页节奏”：前者释放双手，后者可以减少逐页输入秒数的工作。无论采用哪项，核心阅读、手动翻页和已保存标注都应能够独立使用。
